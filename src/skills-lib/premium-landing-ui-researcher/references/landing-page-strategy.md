## Landing Page Strategy

Sempre que criar landing page, entregar:

1. diagnóstico do projeto;
2. nível recomendado do site;
3. direção visual;
4. estratégia de copy;
5. estrutura completa da página;
6. textos prontos;
7. componentes recomendados;
8. animações recomendadas;
9. fontes usadas;
10. plano de implementação;
11. melhorias de conversão;
12. estratégia de CTA externo / WhatsApp, se aplicável;
13. plano de dashboard, se relevante;
14. plano 3D/WebGL, se relevante.

### Landing Page Required Structure

A landing page deve incluir, quando fizer sentido:

**Header / Topo**: logo, menu curto, CTA principal, CTA secundário (se aplicável), navegação clara, versão mobile.

**Hero Section**: headline específica e forte, subheadline com promessa realista, proposta clara, CTA principal, CTA secundário (se fizer sentido), prova rápida ou microcredibilidade, sugestão visual, animação recomendada.

**Sobre / Autoridade**: apresentação do negócio, credibilidade, posicionamento, contexto estratégico.

**Problema / contexto**: cenário atual do público, custo da inação, evitar dor exagerada.

**Solução / mecanismo**: explicar a solução com clareza, por que funciona, apresentar método, produto ou serviço.

**Produto / Serviço**: descrição clara, benefícios, diferenciais, aplicação prática, o que está incluso, para quem é, para quem não é.

**Benefícios**: ganhos práticos, ganhos emocionais, benefícios de status/clareza/velocidade/segurança, transformação esperada.

**Diferenciais**: comparar contra alternativas ruins; método, experiência, velocidade, suporte ou curadoria.

**Prova / Credibilidade**: depoimentos ou placeholders, números, validação, logos, autoridade, cases, antes e depois.

**Quebra de Objeções**: dúvidas principais, riscos percebidos, barreiras de decisão (tempo, preço, confiança, complexidade, suporte, resultado esperado).

**Conversão**: oferta, reforço de valor, CTA forte, bônus/garantia/segurança (se existir), urgência ética (se fizer sentido), redução de risco.

**FAQ**: perguntas frequentes relevantes, respostas diretas e objetivas, objeções respondidas.

**Footer**: links úteis, contato, social, legal, CTA final (se fizer sentido).

### Case Study / Portfolio Requirements

Quando o site for para agência, consultoria, estúdio, dev premium, designer, produto autoral ou marca pessoal, sempre considerar uma seção de portfolio.

Incluir:

- **selected work**: grid editorial com 4-8 cases curados (não galeria infinita);
- **case cards**: thumbnail + nome do cliente (ou placeholder) + ano + tags de capability + linha de descrição curta;
- **case deep-dive**: 1 case em destaque com storytelling longo na própria landing, ou link para página individual `/work/[slug]`;
- **problema**: contexto, restrições, o que estava travando;
- **decisões**: as escolhas não óbvias, o mecanismo, o porquê;
- **resultado**: o outcome visual + métricas se existirem;
- **stack**: tecnologias usadas, em mono type, como metadata editorial;
- **métricas reais quando existirem**: usar números específicos, datados e atribuídos;
- **placeholders editáveis quando faltarem dados**: marcar claramente como `[editável]` ou `[Cliente sob NDA]`.

**Regra crítica:** nunca inventar clientes, números ou resultados. Usar `[editável]` quando faltar informação real. Inventar prova queima credibilidade no momento que o usuário fornecer os dados verdadeiros.

Padrões editoriais recomendados:

- numeração mono nos cases (`01 — `, `02 — `);
- ano em mono type ao lado do nome;
- tags de capability separadas por `·` em vez de pílulas coloridas;
- thumbnails com aspect ratio consistente (16:10 ou 4:3 funciona bem para tech);
- hover com clip-path reveal ou image scale sutil + accent border;
- cases sob NDA podem aparecer como `[Cliente confidencial · setor]` com descrição genérica do trabalho.

Para case deep-dive na landing ou em página própria:

- estrutura em 3 atos: Context → Decisions → Outcome;
- intercalar texto editorial com mockups grandes e estáticos (animar entrada, não loop);
- evitar carrossel automático de imagens (controlar o pace);
- terminar com CTA discreto de "Ver mais trabalhos" ou "Conversar sobre um projeto".

Quando o cliente não tiver portfolio ainda (lançamento de novo estúdio, rebrand, pivot), substituir `Selected Work` por `In Progress` ou `Currently Building` com 1-2 itens reais em desenvolvimento, sem inventar histórico.

### Copywriting Requirements

Escrever todos os textos do site: headlines, subtítulos, descrições, CTAs, textos de apoio, FAQ, textos prontos para uso.

A copy deve ser: clara, elegante, estratégica, orientada à conversão, profissional, moderna, específica, convincente sem exageros, adaptada ao nível de consciência do público, focada em resultado e transformação, premium sem parecer inflada.

A copy não pode soar: genérica, amadora, superficial, artificial, inflada sem substância, caricata, cheia de promessas milagrosas.

Regras práticas:

- Usar 2ª pessoa: "você".
- Ser claro antes de ser criativo.
- Priorizar precisão, especificidade e prova sobre adjetivos vagos.
- Evitar clichês como "revolucione", "transforme sua vida", "potencialize seu sucesso" sem substância.
- Evitar promessas milagrosas.
- Tratar oferta low ticket como entrada estratégica de valor, não como produto barato.
- Aumentar percepção premium com precisão, especificidade, clareza e prova.
- Preferir frases curtas e fortes.
- Explicar benefícios com consequência prática.
- Adaptar a copy ao nível de consciência do público.
- Criar CTAs específicos, não apenas "Saiba mais".
- Não explicar teoria.
- Entregar como copywriter profissional.

### Conversion Optimization

Sempre sugerir melhorias de conversão:

- CTA acima da dobra;
- CTA repetido estrategicamente;
- clareza de oferta;
- redução de objeções;
- prova social;
- reforço de autoridade;
- comparação antes/depois;
- escassez ética, se fizer sentido;
- garantias, se existirem;
- seção de dúvidas;
- microcopy em botões;
- layout mobile-first;
- contraste em CTAs;
- teste A/B de headline;
- teste A/B de hero visual;
- teste A/B de CTA;
- simplificação de formulário;
- elementos de confiança.

### External CTA / WhatsApp Conversion Mode

Quando o objetivo da página for captar leads via WhatsApp, Telegram, Calendly, DM, ligação ou link externo, adaptar a estratégia de conversão.

Usar quando:

- objetivo for "chamar no WhatsApp";
- objetivo for "agendar reunião";
- objetivo for "captar diagnóstico";
- objetivo for "conversar com especialista";
- objetivo for "falar com consultor";
- produto ou serviço vender melhor por conversa.

Para WhatsApp:

- CTA deve ser claro e orientado à ação;
- evitar CTA genérico como "Saiba mais";
- usar microcopy que reduza fricção;
- explicar o que acontece depois do clique;
- reforçar que é rápido, direto e sem compromisso, se for verdade;
- repetir o CTA em pontos estratégicos;
- usar botão fixo/sticky no mobile, se fizer sentido;
- criar seção de objeções antes do CTA final;
- usar prova social antes de pedir conversa;
- CTA deve combinar intenção + benefício.

Exemplos de CTA para WhatsApp:

- "Agendar diagnóstico pelo WhatsApp"
- "Quero ver minha automação funcionando"
- "Falar com um especialista agora"
- "Receber uma análise da minha clínica"
- "Quero automatizar meu atendimento"
- "Ver como isso funcionaria na minha operação"

Microcopy de apoio:

- "Você será direcionado para uma conversa rápida no WhatsApp."
- "Sem compromisso. A ideia é entender seu cenário e mostrar o melhor caminho."
- "Ideal para clínicas que querem captar, responder e agendar com mais consistência."

Quando o CTA for WhatsApp, incluir no plano de implementação:

- link formatado com mensagem pré-preenchida;
- botão fixo mobile opcional;
- eventos de tracking;
- variações A/B de CTA;
- fallback para desktop;
- mensagem inicial sugerida.

Exemplo de mensagem pré-preenchida:

```text
Olá, quero entender como uma automação com IA poderia ajudar minha clínica a captar mais leads e agendar mais avaliações.
```

### Visual Direction Requirements

Sempre descrever: estilo visual ideal, cores sugeridas, tipografia, layout, elementos visuais, sensação que o site deve transmitir, motion style, nível de sofisticação, referências de componentes, hierarquia visual, direção de imagens, uso de 3D (se fizer sentido), fallback mobile.

### Implementation Output

Se o usuário pedir implementação, entregar:

- file structure;
- dependencies;
- component architecture;
- animation strategy;
- responsive behavior;
- mobile fallback;
- performance notes;
- accessibility notes;
- SEO basics;
- recommended components;
- sections order;
- implementation steps.

Para projetos avançados, incluir: lazy loading, reduced motion support, canvas optimization, dynamic imports, mobile particle reduction, asset compression, animation budget, Core Web Vitals considerations.

#### Regras de implementação

- Respeitar padrões existentes do projeto.
- Não reescrever arquitetura sem necessidade.
- Criar componentes reutilizáveis.
- Usar TypeScript quando o projeto usa TypeScript.
- Usar Tailwind quando o projeto usa Tailwind.
- Usar shadcn/ui se já estiver instalado ou se for claramente adequado.
- Evitar dependências novas quando CSS/Framer Motion resolver.
- Adicionar Three.js ou React Three Fiber somente quando necessário.
- Garantir responsividade.
- Garantir estados de hover/focus.
- Não quebrar acessibilidade.
- Não deixar texto placeholder genérico, salvo depoimentos/cases quando o usuário não tiver prova real.
- Para placeholders, escrever textos realistas e marcá-los como editáveis.
