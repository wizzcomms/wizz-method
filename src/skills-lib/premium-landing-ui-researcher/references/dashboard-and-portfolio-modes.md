## SaaS Dashboard Mode

Quando o projeto for SaaS, app, plataforma, AI tool, CRM, analytics product, produto com login, internal tool ou productized service, considerar se o projeto também precisa de dashboard.

Se fizer sentido, criar ou recomendar um dashboard SaaS completo junto da landing page.

O dashboard pode incluir:

- sidebar navigation;
- top bar;
- KPI cards;
- charts;
- tables;
- onboarding state;
- empty states;
- loading states;
- skeleton states;
- error states;
- notifications;
- settings page;
- billing area;
- subscription area;
- user/profile area;
- upgrade prompts;
- usage metrics;
- responsive layout;
- mobile layout;
- command menu;
- activity feed.

A skill decide se o dashboard é necessário com base no tipo de projeto, na presença de login, no modelo de negócio e na pergunta direta ao usuário quando houver dúvida.

Quando o usuário pedir landing + produto, entregar:

1. landing page estratégica;
2. dashboard SaaS sugerido;
3. arquitetura visual compartilhada entre landing e dashboard;
4. componentes principais reutilizados;
5. estados de interface (empty, loading, error, success);
6. plano de implementação faseado.

O dashboard deve seguir a mesma identidade visual da landing page (cores, tipografia, espaçamento, radius, tom). Não tratar dashboard como um produto visual separado da landing.

## Portfolio / Authority Site Mode

Quando o objetivo do site for autoridade, portfolio, marca pessoal, estúdio, agência premium ou lead passivo, **não tratar como sales page agressiva**.

Ativar este modo quando:

- o cliente vende serviço consultivo premium ou high-ticket;
- o objetivo principal é mostrar autoridade e portfolio (não captação direta);
- o público é maduro (founders, C-level, peers, mercado premium);
- a marca é autoral, estúdio, boutique ou agência selecionada;
- o funnel é por inbound qualificado, indicação ou conversa privada;
- pressão de conversão queimaria o posicionamento.

Priorizar:

- manifesto;
- selected work;
- case deep-dive;
- capabilities;
- recognition;
- conversa discreta;
- CTA editorial;
- prova por execução visual;
- copy sofisticada e sem urgência falsa.

Evitar:

- FAQ tradicional se parecer low-end;
- pricing público se o serviço for premium/custom;
- excesso de depoimentos genéricos;
- urgência falsa;
- copy agressiva de funil;
- popups, exit intents e sticky CTAs barulhentos;
- promessas mensuráveis sem prova real ("3x mais vendas em 30 dias");
- elementos de e-commerce em site de serviço autoral.

Quando este modo estiver ativo, ajustar:

- **CTA principal**: editorial e discreto (`Start a conversation`, `hello@marca.com`, `Agendar uma call de 30 min`), não popup, não sticky agressivo;
- **Hero**: statement editorial, não promessa de resultado bombástica;
- **Prova social**: logo grid monocromático + 1-2 quotes editoriais longas, não carrossel de testimonials;
- **Estrutura**: substituir FAQ por case deep-dive; substituir pricing por capabilities + processo;
- **Microcopy**: tom adulto, sem exclamação, sem caps lock estratégico, sem emoji decorativo;
- **Ritmo**: mais espaço negativo, mais respiro entre seções, menos seções no total.

Este modo é compatível com 3D High-End e Signature 3D Experience. A combinação Portfolio/Authority + Signature 3D é ideal para agências premium, estúdios de design/dev e marcas pessoais de especialistas que querem o site funcionar como prova viva de capacidade.

Este modo **não** é compatível com External CTA / WhatsApp Mode agressivo. Se o cliente quiser WhatsApp como CTA, manter o botão discreto no nav e no footer, sem sticky mobile e sem microcopy de urgência.
